## 学习目标

- 能用一句话解释 LLM、Agent、Harness、MCP、Skill
- 能区分 chatbot、workflow 与 agent
- 知道后面每一章分别在学什么

## 0.1 为什么先认名词

Agent 领域的名词很多，而且经常被混着用。先建立一张地图，后面写代码时就不会把“工具”“技能”“协议”“框架”当成同一件事。

这一课不写代码，也不需要 API Key。你只需要能回答三个问题：

1. 它是什么？
2. 它解决什么问题？
3. 它不是什么？

## 0.2 模型侧：LLM、Token、Context、Prompt

**LLM** 是大语言模型。它根据上下文预测下一个 token，把一句话接下去。它不是知识库，也不是数据库；它生成的内容需要被验证。

**Token** 是模型读写文本的计量单位。**Context Window** 是模型一次能看到的 token 上限。上下文越长，成本和延迟通常越高。

**Prompt** 是你给模型的指令与上下文，包括 system、user、assistant 消息。Prompt 不是越长越好，清晰、结构化、有边界更重要。

## 0.3 Agent 侧：Agent、Tool、ReAct

**Agent** 不是“会聊天的机器人”。更准确的定义是：

```text
Agent = LLM + Tools + Loop + State
```

- LLM 负责理解与决策；
- Tools 负责与外部世界交互；
- Loop 让它可以多步执行；
- State 保存上下文、记忆与中间结果。

**Tool** 是 Agent 可以调用的外部函数，例如查天气、读文件、查数据库。模型输出“要调用哪个工具、参数是什么”，由运行时真正执行。

**ReAct** 是一种经典循环：Thought（思考）→ Action（行动）→ Observation（观察），再把观察结果放回上下文，继续下一步，直到给出最终答案。

## 0.4 能力侧：Memory、RAG、MCP、Skill、Harness

| 名词 | 一句话解释 | 不是什么 |
|-|-|-|
| Memory | 保存对话历史、会话状态或长期偏好 | 不是把整段聊天无限塞进上下文 |
| RAG | 先从外部知识库检索，再让模型带着资料回答 | 不是微调，也不是训练新模型 |
| MCP | 连接 Agent 与外部工具/数据源的统一协议 | 不是某个框架，也不是某个模型 |
| Skill | 可复用的流程知识与步骤，通常含说明、脚本或模板 | 不是单个工具接口 |
| Harness | 包在 Agent 循环外的工程外壳：工具协议、权限、状态、trace、评测 | 不是模型本身，也不等于框架 |

<div class="v-callout is-tip">
  <strong>Tool 与 Skill 的区别</strong>
  <p>Tool 是“能调用什么”，Skill 是“这类任务应该怎么做”。一个 Skill 可以调用多个 Tool。</p>
</div>

## 0.5 工程侧：Multi-Agent、Eval、Trace

**Multi-Agent** 是多个角色按职责协作，例如 planner、executor、reviewer。重点在职责边界、输入输出和停止条件，不是角色扮演越多越好。

**Eval** 是评测集与指标：成功率、失败原因、工具调用次数、成本、延迟。

**Trace** 是一次执行的完整轨迹。看 trace 才能判断失败发生在 prompt、工具、检索、模型还是状态管理。

## 0.6 最容易混的四组

<div class="v-callout is-warn">
  <strong>LLM ≠ 知识库</strong>
  <p>模型会生成看起来合理但可能错误的内容；需要检索、引用或工具验证。</p>
</div>

<div class="v-callout is-warn">
  <strong>MCP ≠ 框架</strong>
  <p>MCP 是协议，LangGraph、AutoGen 是开发框架；两者解决不同问题。</p>
</div>

<div class="v-callout is-warn">
  <strong>Harness ≠ 模型</strong>
  <p>Harness 决定工具怎么暴露、权限怎么控制、状态怎么保存、失败怎么回放；它往往比换模型更影响可用性。</p>
</div>

## 0.7 学完自检

- 能用一句话说清 chatbot、workflow、agent 的区别；
- 能说出 tool、skill、MCP 各自解决什么问题；
- 能解释为什么 harness 决定 Agent 是否可交付。

## 小结

- LLM 是大脑，Agent 是能调用工具并循环执行的整体；
- Tool 是可调用接口，Skill 是可复用流程，MCP 是连接协议；
- RAG 是检索增强，不是微调；
- Harness 是工程外壳，决定权限、状态、trace 与评测；
- 稳定任务优先 workflow，开放任务才用 Agent。
