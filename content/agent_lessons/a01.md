## 学习目标

- 用 OpenAI 兼容接口完成一次真实调用
- 看懂 `base_url`、`model`、`messages` 与返回结构

## 1.1 先跑通一次调用

Agent 的所有能力，最终都落到一次或多次 LLM 调用。先把最小调用跑通，再谈工具与循环。

安装依赖：

```bat
pip install requests python-dotenv
```

在项目目录新建 `.env`：

```text
LLM_API_KEY=sk-你的占位Key
LLM_BASE_URL=https://api.deepseek.com/v1
LLM_MODEL_ID=deepseek-chat
```

再新建 `first_call.py`：

```python
import os

import requests
from dotenv import load_dotenv

load_dotenv()
api_key = os.getenv("LLM_API_KEY")
base_url = os.getenv("LLM_BASE_URL", "https://api.deepseek.com/v1")
model = os.getenv("LLM_MODEL_ID", "deepseek-chat")

response = requests.post(
    f"{base_url}/chat/completions",
    headers={
        "Authorization": f"Bearer {api_key}",
        "Content-Type": "application/json",
    },
    json={
        "model": model,
        "messages": [
            {"role": "user", "content": "用一句话解释什么是 Agent"}
        ],
        "temperature": 0,
        "max_tokens": 200,
    },
    timeout=30,
)
response.raise_for_status()
data = response.json()

print(data["choices"][0]["message"]["content"])
print(data["usage"])
```

运行 `python first_call.py`。第一次可能遇到 401、404 或超时，1.9 会集中处理这些错误。

## 1.2 三个关键字段

| 字段 | 作用 | 常见错误 |
|-|-|-|
| `base_url` | API 服务地址，只写到版本前缀 | 多写了 `/chat/completions`，导致路径重复 |
| `model` | 厂商规定的模型 ID | 自己编名字，或用了别的厂商的模型名 |
| `messages` | 对话消息数组 | 传成字符串，或角色名拼错 |

OpenAI 兼容接口的好处是：`messages` 的结构不变，换 `base_url` 与 `model` 就能切换厂商。课程示例使用 DeepSeek，你也可以换成任意兼容服务。

## 1.3 返回结构

最小调用只需要关心两个位置：

```python
text = data["choices"][0]["message"]["content"]
usage = data["usage"]
```

- `choices` 是候选回答列表，通常取第 0 个；
- `message.content` 是模型生成的文本；
- `usage.prompt_tokens` 与 `usage.completion_tokens` 用于估算成本；
- `finish_reason` 为 `stop` 表示正常结束，为 `length` 表示被 `max_tokens` 截断。

## 1.4 跑通之后再改什么

第一次的目标只有“拿到文本”。跑通后可以逐项替换：

1. 换一条 `user` 消息，观察输出变化；
2. 加一条 `system` 消息设定回答风格；
3. 换 `model`，比较速度与质量；
4. 打印 `usage`，观察输入与输出 token 的比例。

## 小结

- Agent 的底层仍是 LLM 调用，先跑通最小请求；
- `base_url` 只写到版本前缀，`model` 用厂商真实 ID；
- 文本在 `choices[0].message.content`，用量在 `usage`；
- Key 只放本机 `.env`，平台不保存、不代调用。
