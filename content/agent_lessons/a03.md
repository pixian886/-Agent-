## 学习目标

- 识别 401、429、5xx 与超时
- 写一个有限次数、带退避的重试
- 估算一次调用的 token 成本

## 1.9 先看状态码

| 状态码 | 含义 | 处理 |
|-|-|-|
| 401 | Key 无效或缺失 | 不要重试，检查 `.env` |
| 403 | 无权限或地区限制 | 检查账户与模型权限 |
| 404 | 路径或模型名错误 | 检查 `base_url` 与 `model` |
| 429 | 请求过多或额度受限 | 等待后有限重试 |
| 500 / 502 / 503 | 服务端暂时故障 | 等待后有限重试 |
| 超时 | 网络慢或服务无响应 | 设置 timeout，有限重试 |

重试的第一原则：**只重试可恢复的错误**。Key 错了，重试一百次也不会成功，只会浪费时间和额度。

## 1.10 timeout 与退避

`requests` 默认可能一直等。所有 LLM 请求都应显式设置超时：

```python
response = requests.post(url, headers=headers, json=payload, timeout=30)
```

一个最小重试骨架：

```python
def call_with_retry(max_attempts=3, base_delay=1):
    for attempt in range(max_attempts):
        try:
            return call_api()
        except RetryableError:
            if attempt == max_attempts - 1:
                raise
            time.sleep(base_delay * (2 ** attempt))
```

- `max_attempts` 必须有上限；
- 等待时间指数增长，避免持续冲击服务；
- 401/403/404 不进入重试分支；
- 最终失败要保留最后一次错误信息。

## 1.11 成本从哪里来

一次调用的成本由输入与输出 token 共同决定：

```text
成本 ≈ prompt_tokens × 输入单价 + completion_tokens × 输出单价
```

`response["usage"]` 会直接给出两个数：

```python
usage = data["usage"]
print(usage["prompt_tokens"], usage["completion_tokens"])
```

控制成本的三个开关：

1. 裁剪历史消息，只保留必要上下文；
2. 设置 `max_tokens`，防止输出失控；
3. 用更小的模型做分类、抽取等简单任务。

## 小结

- 401/403/404 不重试，429 与 5xx 才值得重试；
- timeout 必须显式设置；
- 重试要有上限并使用退避；
- 成本由输入与输出 token 决定，靠裁剪上下文与 max_tokens 控制。
