## 学习目标

- 用字典把多个工具注册到一张表
- 按名称分发调用，并统一处理未知工具与参数错误
- 让每个工具返回一致的结果结构

## 2.5 为什么需要注册表

只有一个工具时，可以写 `if name == "get_weather"`。工具增加到五个、十个，分支会越来越长，新增工具还要改主流程。

注册表把“工具名 → 执行函数”集中到一张字典：

```python
TOOLS = {
    "get_weather": get_weather,
    "query_orders": query_orders,
    "search_docs": search_docs,
}
```

主流程只认名称，不需要知道每个函数的细节。

## 2.6 一个最小注册表

```python
def get_weather(city: str) -> dict:
    return {"ok": True, "result": f"{city} 26℃"}

def query_orders(date: str) -> dict:
    return {"ok": True, "result": ["A001", "A002"]}

TOOLS = {
    "get_weather": get_weather,
    "query_orders": query_orders,
}

def call_tool(name: str, arguments: dict) -> dict:
    tool = TOOLS.get(name)
    if tool is None:
        return {"ok": False, "error": f"未知工具：{name}"}
    try:
        return tool(**arguments)
    except TypeError as exc:
        return {"ok": False, "error": f"参数不匹配：{exc}"}
    except Exception as exc:
        return {"ok": False, "error": f"工具执行失败：{exc}"}
```

三个要点：

1. 未知工具返回错误，不抛异常到主循环；
2. 参数不匹配时给出可读原因；
3. 工具内部异常也转成结构化错误。

## 2.7 统一返回结构

推荐所有工具都返回同一种形状：

```python
{"ok": True, "result": ...}
{"ok": False, "error": "..."}
```

这样 Agent 循环只需要判断 `ok`，不需要为每个工具写不同的错误处理。错误信息要写给模型看，尽量具体：

- `缺少参数 city`
- `days 必须是 1 到 7 的整数`
- `数据库暂时不可用，请稍后重试`

<div class="v-callout is-tip">
  <strong>错误也是观察</strong>
  <p>工具失败时，把错误作为 observation 放回上下文，模型才有机会改参数或换工具。直接让程序崩溃，Agent 就失去了自我修正的机会。</p>
</div>

## 2.8 注册表也要有边界

- 只注册允许模型调用的工具，不要把所有内部函数都暴露；
- 写操作（删除、转账、发邮件）要额外确认或权限校验；
- 参数在进入执行函数前校验，不能只依赖模型自觉；
- 记录每次工具名、参数摘要与耗时，方便排查。

## 小结

- 注册表把工具名映射到执行函数，主流程只负责查表与分发；
- 未知工具、参数错误、执行异常都返回统一结构；
- 错误信息要具体，让模型能据此调整；
- 只暴露允许调用的工具，写操作要额外保护。
