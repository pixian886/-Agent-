## 学习目标

- 把时间、数据库、HTTP 能力包装成工具
- 区分参数错误、业务失败、超时与权限错误
- 让工具失败变成可观察的结果，而不是程序崩溃

## 2.9 三类真实工具

| 工具 | 典型实现 | 失败方式 |
|-|-|-|
| 时间 | `datetime.now()` | 时区错误、格式错误 |
| 数据库 | `sqlite3` 查询 | 表不存在、SQL 错误、无数据 |
| HTTP | `requests.get()` | 超时、404、429、证书错误 |

真实工具与示例工具最大的区别：**它们会失败**。网络会断，数据库会锁，用户会给错参数。

## 2.10 失败分类

| 类型 | 例子 | 处理 |
|-|-|-|
| 参数错误 | 日期写成 `2026/11/03` | 返回格式提示，让模型改参数 |
| 业务失败 | 查询结果为空 | 返回“没有找到”，不是异常 |
| 暂时故障 | 429、超时、数据库锁 | 有限重试或提示稍后再试 |
| 权限错误 | 401、无权访问表 | 不重试，提示检查配置 |

## 2.11 工具失败也要有格式

```python
from datetime import datetime

def query_orders(date: str) -> dict:
    try:
        parsed = datetime.strptime(date, "%Y-%m-%d")
    except ValueError:
        return {"ok": False, "error": "日期格式应为 YYYY-MM-DD"}

    try:
        rows = db.execute(
            "SELECT id FROM orders WHERE date = ?", (parsed.strftime("%Y-%m-%d"),)
        ).fetchall()
    except Exception:
        return {"ok": False, "error": "数据库暂时不可用，请稍后重试"}

    if not rows:
        return {"ok": False, "error": "该日期没有订单"}

    return {"ok": True, "result": [row[0] for row in rows]}
```

注意：参数错误通常**不应该重试**，模型需要改参数；数据库暂时故障可以有限重试；空结果不是错误，但也要明确告诉模型。

## 2.12 轨迹里怎么看出工具失败

一次完整的失败处理轨迹应该包含：

1. 第一次调用与错误观察；
2. 模型对错误的反应；
3. 修正后的第二次调用；
4. 基于真实结果的最终答案；
5. 没有 `error` 类型的步骤——工具错误是 observation，不是程序崩溃。

本课轨迹题会检查这些信号：必需工具、参数、步数上限、工具调用次数、是否出现 error 步骤、最终答案关键词。

## 小结

- 真实工具一定会失败，失败要转成结构化结果；
- 参数错误让模改参数，暂时故障才有限重试；
- 错误作为 observation 放回上下文，Agent 才能自我修正；
- 轨迹里的工具失败应是 observation，而不是 error 步骤。
