## 学习目标

- 说清 ReAct 的思考、行动、观察三步
- 区分 ReAct 与纯思维链
- 知道循环靠什么终止

## 3.1 为什么需要 ReAct

普通对话是一次问答：模型凭已有上下文直接回答。遇到“今天北京适合跑步吗”这类需要实时信息的问题，模型要么不知道，要么编一个看起来合理的答案。

ReAct 让模型先想、再调用工具、再看结果，然后决定下一步。它把“推理”和“与外部世界交互”交替进行。

## 3.2 三步循环

<div class="v-card">
  <img class="v-card-img" src="/static/img/react-loop.svg" alt="Thought、Action、Observation 循环与 Finish 出口">
  <div class="v-card-body">
    <h4>Thought → Action → Observation</h4>
    <p>思考决定下一步，行动调用工具，观察把真实结果写回上下文；信息够了就 Finish，不够就继续循环。</p>
  </div>
</div>

- **Thought**：当前缺什么信息？下一步该查什么？
- **Action**：选择工具并给出参数；
- **Observation**：工具返回的结果，包括错误；
- **Finish**：信息足够，给出最终答案。

关键点：Observation 不是模型编的，是工具真实返回的。把观察放回消息数组，模型下一轮才能基于事实推理。

## 3.3 ReAct 与 CoT 的区别

<div class="v-compare">
  <div class="v-compare-item">
    <h4>CoT（思维链）</h4>
    <p>让模型把推理步骤写出来，但全程只在模型内部进行。没有外部信息，也没有工具结果。</p>
  </div>
  <div class="v-compare-item is-neutral">
    <h4>ReAct</h4>
    <p>推理与工具交替。每一步行动都会产生新的外部观察，下一步基于观察继续。</p>
  </div>
</div>

CoT 适合纯推理题，例如数学、逻辑、代码分析；ReAct 适合需要实时信息或外部动作的任务，例如查天气、查数据库、发请求。

<div class="v-callout is-warn">
  <strong>ReAct 不是唯一范式</strong>
  <p>还有 Plan-and-Execute、Workflow、Multi-Agent 等。任务步骤固定时，直接用 workflow 更稳定。</p>
</div>

## 3.4 文本形式的 ReAct

不依赖框架时，常用提示词约定让模型输出固定格式：

```text
Thought: 我需要查询北京天气
Action: get_weather
Action Input: {"city": "beijing"}
Observation: 北京 26℃，晴
Thought: 信息足够
Finish: 北京今天 26℃，适合跑步。
```

运行时解析 `Action` 与 `Action Input`，执行工具，把结果填到 `Observation`，再让模型继续。

终止条件必须明确：

1. 模型输出 `Finish`；
2. 达到最大步数；
3. 连续重复同一个动作；
4. 出现不可恢复的错误。

没有终止条件的循环，就是死循环。

## 小结

- ReAct 是思考、行动、观察的循环；
- 观察来自真实工具，不是模型编造；
- CoT 只在模型内部推理，ReAct 会与外部世界交互；
- 必须有明确终止条件，优先设置最大步数。
