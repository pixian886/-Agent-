## 学习目标

- 说清为什么要分块

- 实现一个可解释的关键词检索

## 4.5 为什么要分块

一篇文档可能几千字，整篇塞进上下文既浪费 token，也会让模型抓不到重点。分块（chunking）把长文档切成小段，检索时只取最相关的几段。

分块的目标不是“越小越好”，而是：

- 每块能独立表达一个意思；
- 块内有足够上下文，不把一个句子拦腰截断；
- 块大小适合放进提示词，通常几百字。

## 4.6 三种常见分块

| 策略 | 做法 | 优点 | 缺点 |
|-|-|-|-|
| 固定长度 | 每 N 个字符切一段 | 实现简单 | 可能切断句子 |
| 固定长度 + 重叠 | 相邻块重叠一段 | 减少边界丢信息 | 块数变多 |
| 按结构 | 按标题、段落、列表切 | 语义完整 | 依赖文档格式 |

```python
def chunk_text(text: str, size: int = 200, overlap: int = 20) -> list[str]:
    chunks = []
    start = 0
    while start < len(text):
        end = start + size
        chunks.append(text[start:end])
        if end >= len(text):
            break
        start = end - overlap
    return chunks
```

每块最好带元数据：文档 ID、标题、块序号。回答时才能给出引用。

小项目先用关键词检索就能跑通 RAG；文档量大、查询表达多样时再考虑向量检索。两者也可以混合：先关键词召回，再向量排序。

## 4.8 打分与 top-k

一个最小关键词检索：

```python
def search(chunks: list[dict], query: str, top_k: int = 3) -> list[dict]:
    scored = []
    for chunk in chunks:
        score = chunk["text"].count(query)
        if score > 0:
            scored.append({**chunk, "score": score})
    scored.sort(key=lambda item: item["score"], reverse=True)
    return scored[:top_k]
```

改进方向：

1. 把查询拆成多个词，分别计分；
2. 对长块做长度归一化，避免长块天然占优；
3. 保留块 ID，方便引用与去重；
4. 无命中时不要硬凑，返回“没有找到”，让模型明确说不知道。

<div class="v-callout is-tip">
  <strong>先做可解释的检索</strong>
  <p>关键词检索的分数能直接解释。先跑通“检索 → 注入 → 回答”，再换向量检索，排错会容易得多。</p>
</div>

## 小结

- 分块让检索只取相关片段，节省上下文；
- 固定长度、重叠、按结构各有取舍；
- 关键词检索简单可解释，向量检索擅长语义；
- 块要带 ID 与来源，方便引用与排错。
