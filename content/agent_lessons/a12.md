## 4.9 RAG 是五步管道

RAG（Retrieval-Augmented Generation）不是“把文档丢给模型”，而是一条固定管道。

<div class="step-player">
  <div class="step is-active">
    <p>第 1 步：文档入库。清洗文本，切成块，记录文档 ID 与块序号。</p>
    <pre><code>docs/refund.md
→ chunk 0, 1, 2 ...
→ {"doc_id": "refund", "chunk_id": 0}</code></pre>
  </div>
  <div class="step">
    <p>第 2 步：用户提问。把问题原样保留，必要时做改写或抽取关键词。</p>
    <pre><code>query = "退款多久到账？"</code></pre>
  </div>
  <div class="step">
    <p>第 3 步：检索。按关键词或向量相似度取 top-k 个块。</p>
    <pre><code>top_k = 3
chunks = search(index, query, top_k=3)</code></pre>
  </div>
  <div class="step">
    <p>第 4 步：注入。把块内容与来源放进提示词，要求模型只依据资料回答。</p>
    <pre><code>system: 只根据资料回答；
资料不足时说“没有找到”。
user: 资料：[1] ... [2] ...

  </div>
  <div class="step">
    <p>第 5 步：回答与引用。模型给出答案，并标注使用了哪几条资料。</p>
    <pre><code>退款一般 1-3 个工作日到账。[1]</code></pre>
  </div>

## 4.10 最小代码骨架

```python
def answer_with_rag(question: str) -> str:
    chunks = search(index, question, top_k=3)
    if not chunks:
        return "资料库中没有找到相关内容。"

    context = "\n\n".join(
        f"[{item['id']}] {item['text']}" for item in chunks
    )
    messages = [
        {"role": "system", "content": "只根据资料回答，资料不足时明确说没有找到。"},
        {"role": "user", "content": f"资料：\n{context}\n\n问题：{question}"},
    ]
    return call_llm(messages)
```

两点要求：

1. 明确允许“不知道”，否则模型容易编；
2. 把来源 ID 给模型，回答里才能引用。

## 4.11 常见失败

| 现象 | 可能原因 | 先改哪里 |
|-|-|-|
| 检索不到相关块 | 分块太大/太小、关键词不匹配 | 分块与检索 |
| 检索到了但答非所问 | top-k 太多、提示词没约束 | 提示词与 top-k |
| 答案没有引用 | 没给块 ID 或没要求引用 | 上下文格式 |
| 模型编造资料 | 资料不足仍要求回答 | system 约束与拒答 |
| 每次答案不稳定 | temperature 太高 | 降到 0 |

<div class="v-callout is-warn">
  <strong>RAG 不是微调</strong>
  <p>RAG 在推理时检索外部资料，不改变模型参数；微调是继续训练模型。两者解决的问题不同，也可以组合。</p>
</div>

## 4.12 本课的两个练习

- 轨迹题：提交一次完整 RAG 轨迹，检查是否先检索、再读取片段、最后基于资料回答；
- 本地作业：在本机实现文档分块与关键词检索，打印 top-3 块。

轨迹必须来自真实运行；平台只检查 `search_docs`、`read_doc` 等工具调用与最终答案，不运行你的代码。

## 小结

- RAG 五步：入库、提问、检索、注入、回答；
- 检索结果要带来源 ID，提示词要求引用与拒答；
- 失败先分诊：检索、提示词、模型还是数据；
- RAG 是检索增强，不是微调。
