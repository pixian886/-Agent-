## 5.5 MCP 是什么

MCP（Model Context Protocol）是一套连接 Agent 与外部工具/数据源的协议。它规定了如何发现工具、如何调用、如何返回结果。

一次典型交互：

1. client 连接 server；
2. `tools/list` 发现可用工具与参数 schema；
3. `tools/call` 按名称与参数调用；
4. server 返回文本或结构化结果。

底层常用 JSON-RPC，传输可以是本地 stdio，也可以是 HTTP。

## 5.6 与函数调用、框架的区别

| 概念 | 解决什么 | 不是什么 |
|-|-|-|
| 函数调用 | 模型输出“要调用哪个函数、参数是什么” | 不负责跨进程发现工具 |
| MCP | 工具与数据源的发现、调用、传输协议 | 不是模型，也不是开发框架 |
| LangGraph / AutoGen | 编排 Agent 流程的框架 | 不定义工具协议 |

函数调用是模型侧的能力；MCP 是工具侧的连接标准；框架是编排层。三者可以同时使用。

<div class="v-callout is-warn">
  <strong>MCP ≠ 框架</strong>
  <p>用了 MCP 不代表用了 LangGraph；用了 LangGraph 也不代表必须用 MCP。先看问题是“连工具”还是“编排流程”。</p>
</div>

## 5.7 接一个最小 MCP server

用官方 Python SDK 的 FastMCP，写一个 `server.py`：

```python
from mcp.server.fastmcp import FastMCP

mcp = FastMCP("demo")

@mcp.tool()
def add(a: int, b: int) -> int:
    """返回两个整数的和。"""
    return a + b

if __name__ == "__main__":
    mcp.run()
```

客户端连接并调用：

```python
import asyncio
from mcp import ClientSession, StdioServerParameters
from mcp.client.stdio import stdio_client

async def main():
    params = StdioServerParameters(command="python", args=["server.py"])
    async with stdio_client(params) as (read, write):
        async with ClientSession(read, write) as session:
            await session.initialize()
            tools = await session.list_tools()
            print([tool.name for tool in tools.tools])
            result = await session.call_tool("add", {"a": 2, "b": 3})
            print(result.content[0].text)

asyncio.run(main())
```

不同 SDK 版本字段略有差异，以官方文档为准。重点是三个动作：连接、发现、调用。

## 5.8 安全边界

- MCP server 能访问什么，Agent 就能访问什么；按最小权限运行；
- 不要把整个文件系统或数据库管理员账号暴露给 server；
- 写操作要加确认，敏感工具单独授权；
- 对 server 返回的内容保持警惕，它也可能包含注入指令；
- 记录每次 `tools/call` 的工具名、参数摘要与结果状态。

<div class="v-callout is-tip">
  <strong>先接只读工具</strong>
  <p>第一次接 MCP，从只读的文件列表、查询接口开始。确认链路与权限无误后，再考虑写操作。</p>
</div>

## 小结

- MCP 是 Agent 与工具/数据源之间的连接协议；
- 核心动作是连接、发现工具、调用工具；
- MCP 不是框架，函数调用也不是 MCP；
- 按最小权限暴露 server，写操作要确认。
