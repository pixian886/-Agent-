## 学习目标

- 估算一次任务的 token 预算
- 会用缓存、限流与降级控制成本
- 知道哪些指标需要持续观察

## 6.9 成本预算

一次 Agent 任务可能调用模型多次，每次还带工具结果与检索资料，成本远高于单次问答。

```text
任务成本 ≈ Σ（每次调用的输入 token × 输入单价 + 输出 token × 输出单价）
```

控制手段：

1. 设 `max_tokens`，限制单次输出；
2. 裁剪上下文，只带必要资料；
3. 限制最大步数与工具调用次数；
4. 简单任务用小模型，复杂任务才升级；
5. 给每个任务设成本上限，超限终止。

## 6.10 缓存

相同或相似请求可以缓存：

| 缓存对象 | 例子 | 收益 |
|-|-|-|
| 精确请求 | 同一问题、同一上下文 | 直接复用答案 |
| 检索结果 | 同一查询的 top-k 块 | 省检索与 embedding |
| 工具结果 | 天气、汇率等短期不变数据 | 省外部调用 |
| 系统提示 | 固定前缀 | 部分厂商支持提示缓存 |

缓存要设过期时间，并在数据变化时失效。把用户隐私内容长期缓存，会带来新的安全问题。

## 6.11 限流与降级

- **限流**：按用户、IP 或全局限制请求频率，保护服务与额度；
- **并发限制**：同时运行的 Agent 数量要有上限；
- **降级**：高负载时关闭非核心工具、缩短回答、返回缓存；
- **熔断**：连续失败达到阈值时暂停调用，避免持续消耗。

降级要提前设计，不能等额度用完才临时处理。

## 6.12 需要持续观察的指标

- 每个任务的 token 用量与成本；
- 模型调用次数、工具调用次数；
- 缓存命中率；
- 限流触发次数；
- 失败率与失败分类；
- P95 延迟。

## 小结

- Agent 成本来自多次模型调用与上下文长度；
- 缓存、限流、降级、熔断是四项基本控制；
- 预算要写成硬限制，不靠提示词自觉；
- 成本、缓存命中、限流与延迟需要持续观察。
