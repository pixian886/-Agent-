## 学习目标

- 说清多 Agent 的分工方式
- 会设计角色输入、输出与共享状态
- 知道多 Agent 不是越多越好

## 7.1 为什么拆成多个角色

一个 Agent 同时做规划、检索、写作、检查，提示词会越来越长，职责互相干扰。拆成多个角色，每个角色只关注一件事，提示词更短，输出更稳定。

但多 Agent 也带来新问题：消息怎么传、状态放哪、冲突谁裁决、成本怎么控。

## 7.2 常见角色

| 角色 | 负责 | 输入 | 输出 |
|-|-|-|-|
| planner | 拆解任务 | 用户目标 | 步骤列表 |
| researcher | 检索资料 | 查询与范围 | 资料与来源 |
| writer | 组织答案 | 资料与大纲 | 草稿 |
| reviewer | 检查质量 | 草稿与要求 | 通过 / 驳回意见 |

角色不一定要四个。小任务用“执行者 + 检查者”两个就够。

## 7.3 消息与共享状态

两种协作方式：

1. **消息传递**：角色之间直接发消息，适合顺序流程；
2. **共享状态**：所有角色读写同一份任务状态，适合并行与监督者模式。

```python
state = {
    "task": "整理退款政策并回答",
    "plan": [],
    "sources": [],
    "draft": "",
    "review": {"passed": False, "comments": ""},
    "trace": [],
}
```

共享状态要约定字段与写入权限。否则两个角色同时改 `draft`，结果无法复现。

## 7.4 角色设计清单

- 这个角色只做什么？
- 它需要哪些最小输入？
- 输出格式是什么？
- 什么时候算完成？
- 失败时返回什么？
- 它能调用哪些工具？

<div class="v-callout is-warn">
  <strong>角色越多，协调成本越高</strong>
  <p>能用一个 Agent 加清晰提示词解决的任务，不要拆成五个。多 Agent 适合职责确实不同、可并行或需要独立检查的场景。</p>
</div>

## 小结

- 多 Agent 通过分工降低单点复杂度；
- 每个角色要有输入、输出与停止条件；
- 协作可用消息传递或共享状态；
- 共享状态要约定字段与写入权限，避免互相覆盖。
