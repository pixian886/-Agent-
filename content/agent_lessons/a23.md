## 学习目标

- 完成可运行、可演示、可复现的项目交付
- 会写 README、导出轨迹、准备演示脚本
- 能用验收清单自查，而不是只看“能跑”

## 8.5 交付清单

| 交付物 | 内容 | 验收 |
|-|-|-|
| 可运行项目 | 入口脚本、依赖、示例数据 | 新环境按 README 能跑通 |
| 配置模板 | `.env.example`，只含占位值 | 不含真实 Key |
| README | 用途、安装、运行、示例、限制 | 第一次使用的人能照着跑 |
| 轨迹 | `trajectory.json` | task_id 正确、步骤真实 |
| 评测记录 | 任务集、指标、失败分类 | 至少 5 个任务 |
| 演示脚本 | 3 分钟流程与话术 | 现场可复现 |
| 截图或录屏 | 关键界面与结果 | 能证明真实运行 |

<div class="v-callout is-warn">
  <strong>不要提交 .env、数据库和缓存</strong>
  <p>交付前检查 `.gitignore`，确认没有 Key、`data/`、`__pycache__/`、`.venv/`。示例配置只保留占位值。</p>
</div>

## 8.6 部署与密钥

本机演示优先，有服务器再按 `DEPLOY.md` 部署。

本机启动：

```bat
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env
python main.py
```

服务器部署：

- 使用 `deploy/docker-compose.yml` 与 Caddy；
- Key 只放在服务器环境变量或 `.env`，不写进镜像；
- 对外只暴露 HTTPS 端口；
- 日志不打印 Authorization 头与完整 Key；
- 平台本身不保存学员 Key，也不代调用模型。

```text
.env.example
LLM_API_KEY=sk-your-key
LLM_BASE_URL=https://api.deepseek.com/v1
LLM_MODEL_ID=deepseek-chat
```

## 8.7 演示脚本

演示不是把项目跑一遍，而是按顺序证明四件事。

| 时间 | 内容 | 要证明 |
|-|-|-|
| 0:00–0:30 | 背景与目标 | 解决什么问题，谁用 |
| 0:30–1:30 | 典型任务 | 工具调用、检索、答案引用 |
| 1:30–2:15 | 失败或注入案例 | 错误处理与安全边界 |
| 2:15–3:00 | 轨迹与评测 | 可复现、有指标、不是碰巧成功 |

演示前准备：

1. 清空无关数据，保留可复现的示例；
2. 准备一个会失败的输入，展示错误处理；
3. 打开 `trajectory.json`，能指出关键步骤；
4. 记住评测指标，不只说“效果不错”。

<div class="v-callout is-tip">
  <strong>演示失败案例比只演示成功更加分</strong>
  <p>能解释失败发生在检索、工具、提示词还是模型，说明你真的理解系统，而不是背答案。</p>
</div>

## 8.8 验收与常见问题

自查清单：

- [ ] 新环境按 README 能跑通；
- [ ] `.env.example` 无真实 Key；
- [ ] 典型任务成功，答案有引用；
- [ ] 空结果与参数错误有明确提示；
- [ ] 注入案例没有执行危险工具；
- [ ] 轨迹 task_id 正确，步骤来自真实运行；
- [ ] 至少 5 个评测任务，记录成功率、步数、成本；
- [ ] 3 分钟演示可完整走完；
- [ ] 仓库没有 `.venv/`、`data/`、`__pycache__/`。

常见问题：

| 问题 | 处理 |
|-|-|
| 换电脑跑不起来 | 补 requirements、示例数据与 README |
| 轨迹 task_id 不匹配 | 按题目要求重新导出 |
| 演示时超时 | 准备离线示例或缓存结果，并说明降级 |
| 工具失败直接崩溃 | 把错误转成 observation 返回 |
| 只有成功案例 | 补空结果、错误参数与注入测试 |

## 小结

- 交付物不只是代码，还包括 README、配置模板、轨迹与评测记录；
- Key 只放环境变量，不提交、不打印；
- 演示按背景、典型任务、失败案例、轨迹与评测四段走；
- 用验收清单自查，确保换台电脑也能复现。
